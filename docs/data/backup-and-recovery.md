# 备份与恢复

[数据目录](README.md) · [文档首页](../README.md)

阅读资料备份用于换机、重装和书库恢复。它把资料打包成 ZIP，导入时先验证和预览，再与设备现有资料合并。界面入口在 [LibraryBackupScreen](../../app/src/main/java/cc/novelia/app/ui/settings/LibraryBackupScreen.kt)，实现位于 [data/backup](../../app/src/main/java/cc/novelia/app/data/backup)。

## 选对迁移方式

| 需求 | 使用方式 |
| --- | --- |
| 复制部分阅读、外观和屏蔽偏好 | 普通设置 JSON |
| 分享标签译名和分类 | 标签库 JSON |
| 保留书架、笔记、草稿和本地小说 | 阅读资料 ZIP |
| 同步原站账号的收藏和章节历史 | 原站云端同步 |
| 多设备合并选定的网络阅读资料 | [WebDAV](../network/webdav-sync.md) |
| 导出一本小说 | 书籍文件导出 |

系统自动备份已禁用。卸载或更换签名前先导出，并通过预览核对备份可读及缺失提示。

## ZIP 包含什么

包含书架与分组、位置和历史、书签笔记、草稿、阅读偏好、屏蔽和搜索资料、本地文档与插图、文库挂载关系、个人术语及标签词典。论坛收藏保存在论坛账号中，不包含在本地备份内；旧备份中的文章收藏不再恢复。原始 EPUB/TXT/SRT 文件可选，前提是本机还保留它们。

不包含登录令牌、Cookie、WebDAV 密码、网络正文与图片缓存，也不携带待同步队列、下载任务或同步运行状态。下载文件要先导入为文档才会随资料备份；只留在下载目录里的成品需要另行导出。

ZIP 没有加密。SHA-256 检查内容是否完整，不证明来源可信。缺失文档会在清单和预览中说明，不能把导出成功理解成所有原始资料都齐全。

## 导出和恢复流程

导出先刷新书库与标签，再取得净化后的快照。分块本地文档转换为含完整正文的便携 JSON，图片单独收集。清单 `manifest.json` 使用 `format = "novelia-library"`、`version = 1`，记录资源长度和哈希。

```mermaid
flowchart LR
    A[选择 ZIP] --> B[解包到 UUID 暂存目录]
    B --> C[校验并显示预览]
    C --> D[用户确认]
    D --> E[重新校验]
    E --> F[安装或复用文档]
    F --> G[合并最新书库并提交]
    G --> H[合并标签 / 清理暂存]
```

`prepare(input)` 建立暂存，UI 只保存不透明 UUID。`preview` 和 `restore` 会重新校验。提交基于**确认时最新的本地状态**，避免覆盖用户在预览期间的新修改。

## 遇到相同资料怎么处理

| 对象 | 当前合并规则 |
| --- | --- |
| 同一网络书籍、笔记 ID、文章 ID | 本机已有项优先，补入缺失项 |
| 同一书籍的位置 | 比较 `updatedAt`，保留较新记录 |
| 同名草稿、单书设置、个人术语 | 本机值优先 |
| 屏蔽、分组和搜索 | 合并去重；命名搜索按 ID，本机同 ID 优先 |
| 标签和分类 | 同名分类合并，标签按原文；本机已编辑译名和归类优先 |
| 全局偏好 | 本机书架、位置、笔记均为空时才以导入偏好为基础 |
| 本地文档 | 内容及图片一致时复用，否则创建新 ID 并重映射引用 |
| 当前下载和原站待办 | 保留本安装已有状态，不从备份注入任务 |

源文件哈希仅用于缩小文档候选范围。即使哈希相同，现有正文损坏也不能复用。新建文档后，进度、笔记、单书偏好和文库父子关系都要跟随新 ID；已有原件不会被恢复流程随意覆盖。

普通备份会移除 WebDAV 设备身份和同步版本，换机恢复不复制另一台设备的身份。

## 格式校验

[LibraryBackupArchive.kt](../../app/src/main/java/cc/novelia/app/data/backup/LibraryBackupArchive.kt) 检查实际读取字节，而非只信任 ZIP 声明：

| 项目 | 限制 |
| --- | --- |
| 清单 | 16 MiB |
| 单资源 | 128 MiB |
| 总解压量 | 1 GiB |
| ZIP 项数 | 30,000 |
| 路径 | 明确白名单，拒绝越界、重复、目录项及未引用资源 |
| 内容 | 长度、SHA-256、标识、设置范围、分卷和图片引用必须一致 |

这些是整库备份限制，和[单本导入/下载上限](../features/files-and-downloads.md#容量限制)不同。新增类型需要同步导出收集、白名单、校验、预览、合并、重映射和回滚。

## 失败时会留下什么

恢复先安装文件，再提交书库，最后合并标签。提交前失败会回滚本次新安装文件，保留现有资料；书库已经提交而标签保存失败时返回部分成功，并保留暂存供重试。界面不能把这种结果显示成整库恢复失败。

启动时发现主状态损坏会进入保护状态，尝试良好副本但阻止普通写入。用户确认恢复后才调用 `commitRestore`，保留损坏原件并使旧待写快照失效。详见[持久化](data-and-storage.md#读取失败为什么进入保护状态)。

回归入口是 [LibraryBackupTest](../../app/src/test/java/cc/novelia/app/data/backup/LibraryBackupTest.kt) 和 [LibraryBackupFlowTest](../../app/src/androidTest/java/cc/novelia/app/data/backup/LibraryBackupFlowTest.kt)。重点检查损坏资源、超限、相同来源但损坏的本地副本、预览期间修改、取消和标签部分失败。
