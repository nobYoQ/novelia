# WebDAV 多设备同步

[网络目录](README.md) · [文档首页](../README.md)

WebDAV 用用户自己的 HTTPS 服务，在设备之间合并选定的阅读资料。它与原站收藏/历史同步独立，**不传输本地小说文件**；迁移本地文档使用[阅读资料备份](../data/backup-and-recovery.md)。

## 首次连接

在“设置 → WebDAV 多设备同步 → 同步服务器”填写地址和凭据，保存并测试。回到同步页选择范围，预览后加入数据集；首次设置可选择以本机或远端偏好为基础，普通资料按记录合并。

改变服务地址、账号或目录会解除原绑定并清除旧密码，需要重新配置。新设备的空集合不会被理解为删除远端全部资料。

## 七类资料分别开关

| 范围 | 同步内容 |
| --- | --- |
| 本地设置 | 可迁移界面/阅读偏好、网络书籍单书设置、屏蔽 |
| 标签库 | 原文、译名、分类、空分类、顺序和使用记录 |
| 本地收藏 | 网络书籍摘要、收藏夹、归属与排序 |
| 阅读进度 | 网络书籍章节、原文段落、内容指纹和阅读时间 |
| 书签 | 网络书籍位置、摘录和标题快照 |
| 笔记 | 网络书籍笔记正文及关联位置 |
| 阅读历史 | 网络书籍最近阅读章节、书名和时间 |

所有范围都排除本地文档、导入分卷及其关联资料，也不传正文、封面字节、下载、缓存、草稿、登录凭据或原站待办。收藏只有书目摘要，不代表另一个设备已下载小说。

亮度、电子纸和翻页等设备偏好默认排除，可在设置范围下单独开启。关联字段整组同步，首次加入这部分需再次预览。关闭某类同步不会删除任一端已有数据；重新开启后合并离线修改，未加入过的范围需要确认。

## 怎样判断哪个修改更新

实现位于 [data/webdav](../../app/src/main/java/cc/novelia/app/data/webdav)。`SyncReplica` 用设备计数器和版本向量记录因果关系，随业务状态原子保存；标签库有自己的版本记录。**不靠两台设备的系统时间判断胜负。**

- 收藏夹和分类有稳定 ID，重命名保留身份。
- 不同字段可以分别合并；普通并发字段确定性选择，同时保留候选。
- 删除保存墓碑，并发删除优先。看到删除后重新添加会产生新版本；墓碑目前不自动清理。
- 默认标签不能覆盖用户编辑，包括明确清空的译名。
- 同步期间发生的本地编辑会重新应用到合并结果。

进度把章节与段落视为完整锚点，不能从不同设备各取一半。并发进度保留本机位置并展示候选；笔记正文并发修改也供用户选择。选择会生成观察了所有候选的新版本，供后续设备收敛。

布局或译文不同、正文变化时，以原文段落恢复并清除失效字符/像素偏移。普通 ZIP 备份移除设备身份和同步版本，恢复不会克隆另一台设备的身份。

## 同步过程与失败保护

远端目录有协议/数据集 `manifest.json` 和七类独立 JSON。每类独立提交，部分失败保留已成功的结果。

上传前先持久化本地操作和逻辑时钟，上传成功后再应用业务值与确认缓存。配置代次改变或停用同步会阻止旧结果落地。已绑定目录的 manifest 或已同步文件消失时停止，不用本机快照擅自重建。

未知协议、错误数据集、非法引用、损坏或超限载荷都拒绝写入本机。单个响应上限 16 MiB，UTF-8 和容器深度等也会校验；本机资料损坏时保护原文件，同步缓存损坏则要求重新预览。

服务器必须支持可靠的版本和条件更新，不能退化成无条件覆盖。ETag、坚果云兼容和重试细节见[WebDAV 传输协议](webdav-transport.md)。

## 自动同步何时发生

| 触发 | 行为 |
| --- | --- |
| 进入前台 | 尝试同步，此后前台每三分钟检查 |
| 本地修改 | 先落盘并合并一次性任务；前台约十秒后同步 |
| 后台周期 | WorkManager，支持 15/30/60/360 分钟，默认 30 分钟 |
| 手动立即同步 | 自动同步关闭时仍可使用 |
| 关闭启用开关 | 取消自动任务并使当前配置代次失效 |

后台默认要求非计费网络，实际执行受 Android 调度约束，不能保证精确时刻。连续翻页不会无限推迟首次提交；关闭最后一个同步项会停用同步。界面按类型显示成功、待提交、错误和需要选择的冲突。
