# 网络诊断与日志

入口：设置 → 下载与同步 → 网络诊断与日志。

## 收集故障信息

1. 保持发生故障时的 Wi-Fi、移动网络或 VPN 状态，运行网络诊断。
2. 检测最长约三分钟，会逐项显示结果。可以取消；关闭面板不会终止检测。
3. 如果仅特定页面或下载出错，开启「记录问题复现过程」，回到原页面操作一次，再回来停止记录。
4. 点击「导出网络日志」，选择保存位置，将生成的 ZIP 文件交给维护者。
5. 如需对比 Wi-Fi、移动网络或 ECH 开关，请分别检测并导出，避免混淆现场。

详细记录默认关闭，开启后最多持续 30 分钟，应用进程重启后关闭。主动诊断不依赖这个开关，始终记录自身的阶段信息。请求日志在应用私有、禁止备份的目录中轮换，两个文件合计不超过 1 MiB，另有最近诊断摘要。用户可手动清空。日志不会自动上传。

## 为什么能使用但旧诊断会超时

旧诊断调用依赖库的独立 `Probe`：使用独立 DNS/ECH 缓存、单次连接和不带 ALPN 的握手；实际请求使用本项目的传输实现，协商 h2 / http/1.1，可复用连接，并对尚未发送 HTTP 字节的无请求体 GET/HEAD 做最多三次连接尝试。两者使用的连接池和超时策略不同。因此单独一次 Probe 超时，不能证明业务请求不可用。

新版检测直接使用业务同款 ECH 拦截器和原生传输，并与系统 DNS / OkHttp 的直连路径进行对照。诊断使用独立连接池和匿名请求，不重置业务连接，也不改变 ECH 开关。每次检测先清空诊断连接池；同一域名的后续接口检测可以复用连接，原生日志区分 `new` / `reused`。

当前原生解析器只选 A 记录中的 IPv4 地址，而系统直连可能使用 IPv6。原生 ECH 不使用 Android 的系统 HTTP 代理；设备级 VPN 仍可能影响其流量。DoH 服务、服务器地址及协议路由差异都可能导致设备间表现不同。没有故障设备的分阶段日志，不能进一步断言是 DNS 污染、SNI 阻断或服务端故障。

## 检测内容与边界

- 小说、认证、论坛域名的匿名连通请求。
- 网络小说列表、文库列表、论坛分类和帖子列表的读取与 JSON 检查。
- 每个项目分别执行直连和 ECH，总共 14 项，同时最多两个请求。
- 单次连接尝试 8 秒，读取/写入阶段 20 秒，单请求总时限 35 秒，整轮 180 秒。
- 不发送登录凭据，不修改服务端数据，不下载完整小说。账号权限、登录状态及实际下载问题需用「记录问题复现过程」补充。
- HTTP 401/403/429、JSON 结构变化、正文读取失败、TCP/TLS 失败分别呈现。响应成功不代表登录或下载保存成功。
- 响应体只为检查完整读取和解析使用，上限 2 MiB，不写入日志；超限单独报告。

## ZIP 内容和分析方式

`diagnosis.txt` 是最近诊断摘要；`environment.json` 是导出时应用版本、Android 版本、设备型号、ABI、网络类型、VPN、私有 DNS、系统 HTTP 代理、IPv4/IPv6 配置及网络验证状态。

`network-current.jsonl` 和 `network-previous.jsonl` 每行一个结构化事件，按 `timeMs` 排序；`id` 关联一次请求，`run` 关联一轮诊断，`scope` 区分业务与主动诊断。`target` 是固定接口类别，不是完整路径。`elapsedMs` 是请求内的相对时间，原生阶段另有耗时和尝试序号。

记录开始、诊断开始和网络属性变化时也写入环境快照，便于区别故障时与导出时的网络。原生 `exchange` 区分同一请求中的多个重定向连接；`native.doh_provider` 是从固定解析器错误中提取的提供者和失败分类，不包含错误原文。

原生事件会在收到响应头、结束读取或取消时批量取回，`timeMs` 是桥接采集时刻。分析单次原生交换中的先后顺序时，应使用 `exchange` 和 `elapsedMs`；阶段本身的耗时见 `durationMs`。

建议依次检查：

| 事件或表现 | 能说明什么 |
| --- | --- |
| 环境无已验证网络、强制门户 | 系统尚未确认外网可用；仍以实际请求为准 |
| 直连 `dns` 失败 | 系统解析路径失败 |
| `native.doh_ech` 失败 | ECH 路径未取得匹配的地址和 ECH 配置，尚未开始目标 TLS |
| `native.resolution` | 成功选择的 DoH 提供者、地址族及服务器公网 IP；私网地址仅标记 non_public，不含原始解析响应 |
| `tcp` / `native.tcp` | 目标连接建立阶段，结合重试序号判断是否持续失败 |
| `tls` / `native.tls`、`native.ech` | TLS 协商、证书问题、ECH 拒绝或已接受 ECH |
| `native.connection=reused` | 当前请求使用已有连接，不等价于新建连接仍然可用 |
| `response_headers` 后失败 | 已收到 HTTP 响应，应检查正文读取、大小和格式 |
| `call=closed` | 提前关闭，不应当视为完整下载成功 |
| 仅直连可用 | 比较地址族、系统代理和 DoH/ECH 阶段；不要仅凭此认定域名被封锁 |
| 仅 ECH 可用 | 直连的 DNS/TCP/TLS 存在差异，需要结合失败阶段继续分析 |

原生连接重试只允许在未取得连接、尚未发送 HTTP 字节前进行。日志系统不会引入写请求重试、自动降级或证书校验绕过。

日志不保存完整 URL、查询参数、账号、令牌、Cookie、请求/响应头原文、正文、搜索词、文件名、异常原文、SSID、本机 IP、设备序列号或证书内容。日志写盘在独立有界队列执行；队列拥塞或写盘失败不会中断网络请求，导出说明中记录丢弃计数。日志不接入 Android 全局 logcat。

## 开发验证

单元测试覆盖匿名两路检测、渐进结果、取消传播、HTTP 错误与格式错误区分、响应完整性、原生分阶段事件、重试分类、日志轮换、ZIP UTF-8、请求/响应敏感字段排除及关闭记录。设备测试需验证真实原生桥接与日志导出；故障用户网络的最终原因以其导出的日志为准。

2026-10-02 验证：Go 测试通过，422 项 JVM 单元测试通过，Debug / AndroidTest 编译和 lint 通过（0 错误）。现有 API 35 x86_64 专用模拟器通过记录开关、ZIP 导出以及文件选择器期间界面重建测试；真实网络下 14 项直连/ECH 检测均返回 HTTP 200，导出文件包含原生 DNS/ECH、TCP、TLS、连接复用等阶段事件。开启业务记录时，TXT 和 EPUB 的实际后台下载与保存也通过。未在故障用户的设备和网络上验证，不能据此认定其连接问题已经解决。
